# SaaS Hero Escape System

Use this for SaaS, startup, product, AI tool, CRM, devtool, and landing-page hero work. The goal is to escape the default AI SaaS hero before writing code.

## Reject The Default Stack

Do not start from this stack unless the user explicitly asks for it and the product evidence justifies it:

- Logo/nav row.
- Huge headline.
- Explanatory paragraph.
- CTA pair.
- Floating stats row.
- Framed software window.
- Soft grid, mesh, glow, or gradient background.

This stack is not automatically wrong, but it is the current generic default. If you use it, add a stronger composition move and visible product proof early.

## Choose One Escape Move

Pick at least one before coding:

- **Artifact-led:** product artifact dominates; headline supports it.
- **Editorial crop:** show one enlarged product slice with metadata around it.
- **Task first:** lead with a queue, approval, selected task, or next action.
- **Object detail:** show one record, file, contact, product, job, ticket, clip, order, or deployment.
- **Before/after:** show input, transformation, and output.
- **Timeline:** show a sequence of signals, changes, or decisions.
- **Transcript/message:** show conversation, call, email, or notes becoming an action.
- **Table/detail workspace:** rows plus selected detail and attached actions.
- **Canvas/editor:** input surface, controls, preview, and export.
- **Control surface:** a real configurator, scrubber, command palette, or stateful tool.

## Vague Prompt Rule

If the user gives a vague product prompt, invent a sharper product moment before coding.

- CRM: stale deal rescue, follow-up approval, call note to task, handoff, account detail, pipeline action.
- AI tool: source input, generated output, confidence or edit controls, export.
- Devtool: failing log, diff, deploy trace, CLI command, config object, alert.
- Finance/ops: table row, exception queue, approval, ledger item, reconciliation state.
- Creative tool: canvas, timeline, layers, assets, export state.

Do not invent a fake brand-heavy story. Invent the smallest believable user job.

## Brand Fallback

When no brand exists, create a deliberate minimal identity instead of placeholder branding:

- Use the product category as a quiet descriptor, not the whole brand.
- Add a small symbol, wordmark rhythm, or product-shaped mark.
- Avoid black square initials plus generic category text as the full identity.

## Metrics Rule

Metrics are proof only when attached to visible product state.

- Good: metric appears on a row, selected object, export, queue, chart with controls, or before/after.
- Weak: three loose numbers under the hero with no connection to the artifact.

## Mobile Rule

Mobile must reveal product proof early. No mobile first viewport should be only brand, badge, giant headline, paragraph, and stacked CTAs.

If the artifact cannot fit, show a focused crop, selected record, output card, or active task instead of shrinking the whole desktop preview.
