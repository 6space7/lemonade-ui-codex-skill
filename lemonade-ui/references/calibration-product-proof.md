# Calibration: Product Proof

Use this when the design feels polished but vague, like a good-looking shell around generic claims.

## Failure Pattern

- The main visual is decorative or abstract.
- Product copy says "automate", "analyze", "manage", or "grow" without showing the work.
- Mockups use generic labels that could fit any SaaS.
- The page depends on brand name, gradient, or animation to feel specific.

## Better Direction

- Show the product doing one real job.
- Replace vague cards with inspectable product evidence: rows, files, previews, selected states, timelines, forms, media, quotes, logs, or metrics.
- Use domain nouns from the user's product, not invented sample-company names.
- Design a real surface first, then make it beautiful.

## Implementation Cues

- Add a selected item, active state, or before/after result.
- Include realistic data density for the domain.
- Use proof that changes the layout, not just a row of stats below the hero.
- Pair every big claim with a visible object or state.

## Checklist

- If the logo is hidden, can someone still tell what kind of product this is?
- Are labels specific enough to inspect?
- Is there at least one believable state change or outcome?
- Did copy move into the interface wherever possible?
