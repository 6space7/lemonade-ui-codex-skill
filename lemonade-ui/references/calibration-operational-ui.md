# Calibration: Operational UI

Use this for dashboards, admin panels, internal tools, consoles, CRMs, scheduling tools, analytics surfaces, and repeat-use workspaces.

## Failure Pattern

- The UI looks like a landing page wearing dashboard labels.
- Oversized cards waste space that operators need for comparison.
- Charts and metrics appear without filters, rows, actions, or detail states.
- A dashboard is used as hero decoration instead of a repeat-use work surface.
- Decorative motion, shadows, and rounded panels reduce scannability.

## Better Direction

- Prioritize density, scan speed, task flow, and state clarity.
- Use tables, lists, filters, tabs, detail panes, status chips, logs, and clear action buttons.
- Keep typography compact and calm.
- Make the primary repeated task obvious within the first viewport.
- If using a dashboard, include filters, rows/events, selected detail, actions, and at least one concrete state.

## Implementation Cues

- Start with the operator's current status and next action.
- Use one strong table/list/detail pattern before decorative cards.
- Group controls by task frequency.
- Preserve alignment and row rhythm over expressive hero composition.
- Use motion for confirmation, selection, and navigation only.

## Checklist

- Can a returning user scan the screen in seconds?
- Is there enough real data density for the task?
- Are actions attached to the records or states they affect?
- Does every panel justify its space?
