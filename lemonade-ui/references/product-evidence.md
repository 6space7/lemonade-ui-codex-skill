# Product Evidence

Use this when the design feels vague, fake, generic, or when copy is explaining a product the UI should prove.

## Rule

Show the product doing the job.

Good product evidence can be:

- Real app screenshots.
- Believable mock UI with concrete labels and states.
- Tables with domain-specific rows.
- Timelines, editors, inboxes, checkout forms, galleries, dashboards, calendars, device frames, command palettes, location views, or file objects.
- Real photos or generated bitmap imagery that reveal the thing being sold.
- Proof: metrics, quotes, review counts, export states, logs, before/after, or customer artifacts.

## Credibility Details

Add details users can inspect:

- Names.
- Dates.
- Statuses.
- Counts.
- File types.
- Prices.
- Locations.
- Tags.
- Errors.
- Empty/loading/selected states.
- Verified/unverified states.

Avoid generic cards named:

- Analytics.
- Insights.
- Growth.
- Automation.
- Revenue.
- Engagement.

These are acceptable only when surrounded by specific data.

## Product Surface Patterns

- **Queue/detail:** list on one side, selected record on the other.
- **Record/detail/outcome:** selected record, field states, review notes, finished output.
- **Editor/result:** input canvas, settings, generated output, export.
- **Inbox/action:** incoming items, triage, suggested action, approval.
- **Commerce/configure:** product media, variants, price, shipping, purchase action.
- **Ops dashboard:** filters, table, status, detail pane, repeated task controls.

## Logo-Hide Test

Hide the logo. If the page still feels like any random SaaS, add stronger product evidence.

## Copy Transfer

When copy explains a workflow, move it into the UI:

- Paragraph says "reviews records" -> product surface shows selected rows, field states, and approval controls.
- Paragraph says "exports reports" -> show a ready count, file type, and export control.
- Paragraph says "books meetings" -> show calendar slots, attendees, and confirmation state.
- Paragraph says "reduces support load" -> show ticket queue before/after and resolved count.
